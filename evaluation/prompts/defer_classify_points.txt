You are preparing a stateful evaluation of a web agent. You will classify each answer key point into how it must be verified.

There are two kinds of key points:

1. `answer_bearing`
   The final answer text itself must explicitly contain this information for the task to be solved.
   Typical cases:
   - the answer must name a specific entity, product, recipe, place, or item
   - the answer must state a specific value, list, address, time, or set of details
   - the requirement is about what the answer says, not about how it was found
   These are checked against the final answer text.

2. `evidence_bearing`
   This requirement cannot be confirmed from the answer text alone; it must be verified from the agent's trajectory evidence. That evidence is modality-agnostic and equally valid from either execution path: a search/scholar/visit/code text result (snippet, candidate page, paper metadata, visited page or PDF text, computed output) OR a visible browser page state / full-page screenshot.
   Typical cases:
   - a numeric or status constraint that must hold in the trajectory evidence — a search/visit text result, a computed output, OR a visible page state/screenshot (rating threshold, review count, in-stock, sorted order, "lowest price among results", "ranked second after sorting")
   - the answer must be sourced from a specific website, confirmed by trajectory evidence from that site (a search/visit result or page text from that domain, OR a browser page reached at that URL)
   - a filter or condition the trajectory evidence must demonstrably satisfy (search/visit results or computed output showing the qualifying set, OR a visible filtered page state/screenshot)
   These are checked by reading the trajectory step by step.

A key point can require BOTH at once. Many requirements are dual: the value must appear in
the answer text AND must be verifiable in the trajectory evidence (a search/visit/scholar text
result OR a visible source page/screenshot). For these, assign both axes.
Examples of dual (`["answer", "evidence"]`):
- "the answer must report the rating, which must be above 4.0" — the answer must state the rating (answer) AND the trajectory evidence must establish >4.0, whether from a search/visit result or a visible page/screenshot (evidence)
- "the answer must give a specific in-stock product" — names a product (answer) AND in-stock must be established by the trajectory evidence, from a search/visit result or a visible page/screenshot (evidence)
Examples of single `answer` only:
- "the answer must detail the cooking method / list the ingredients / give the total time" — purely about answer text content
Examples of single `evidence` only:
- "the answer must be sourced from X website" / "the evidence trail must show sorting" / "filtered by red color" — pure provenance/filter/sort constraints the answer need not restate

Decision rules:
1. For each key point, assign one or both axes: `answer` (the final answer text must explicitly contain this) and/or `evidence` (the trajectory/page must verify this).
2. Assign BOTH when the requirement is genuinely dual — the fact must be stated in the answer AND demonstrably true in the trajectory evidence (a search/visit text result or a visible page/screenshot). Do not default to dual; assign it only when both are truly required.
3. Assign `evidence` only (not answer) for pure provenance/filter/sort/source constraints the answer does not need to restate.
4. Assign `answer` only for requirements purely about what the answer text says, with no page-state fact to verify beyond the answer itself.
5. Do not merge, split, reword, drop, or add key points. One classification per input key point, in order.
6. Use the task to disambiguate. Base the classification on what the requirement demands, not on whether the agent succeeded.

You will receive the task and the ordered key points. Return JSON only:
{
  "classifications": [
    {"point_id": 0, "axes": ["answer"], "reason": "short"},
    {"point_id": 1, "axes": ["evidence"], "reason": "short"},
    {"point_id": 2, "axes": ["answer", "evidence"], "reason": "short"}
  ]
}

Each `axes` is a non-empty list containing "answer", "evidence", or both. The `classifications`
array must have exactly one entry per input key point, with `point_id` matching the input index
order starting at 0.
